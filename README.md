# 养鱼大亨 · Fish Tycoon 网页复刻版

致敬 2004 年经典模拟经营游戏 **《Fish Tycoon》** 的网页复刻版。从一对成年鱼起家：育种、繁殖、养大、定价、卖鱼，目标是育出 **7 条会改变玩法的魔法鱼**。

界面与玩法对齐原版《Fish Tycoon》（原版截图曾作为参考放在 `references/`，现已清理），主设计文档见 `canvas/documents/main-design.md`。

## 一、运行与构建

```bash
npm install      # 安装依赖
npm run dev      # 本地开发服务器（Vite，默认 http://127.0.0.1:5173）
npm run build    # 类型检查 + 产出 dist/ 静态站点
npm run preview  # 本地预览构建产物
```

- Node 18+，包管理器 npm（仓库带 `package-lock.json`）。
- 技术栈：**TypeScript + Vite**，无前端框架。
- `vite.config.ts` 里配置了 `base: './'`，`dist/` 可以直接放到任意静态托管的任意路径下。
- 构建 = `tsc --noEmit && vite build`，类型不过不会产出产物；当前产物约 2.3 MB（主要是 8 张 WebP 场景图）。

## 二、玩法总览

```
选鱼 → 投食 → 长大成年 → 配对繁殖 → 新品种 / 新鳍基因 → 移入销售缸定价
  ↑                                                        ↓
  └────────── 装备 · 陈设 · 三条研究线 ←──────────── 顾客购买 → 现金
```

开局：**$500 现金、1 号缸 + 销售缸、2 条成年鱼（一雌一雄）+ 2 枚鱼卵、4 罐普通鱼粮**。
目标：凑齐 7 条魔法鱼并让它们活着待在缸里（每条都会改变玩法）。

## 五、育子系统：441 个品种

**441 = 21 个鱼种 × 21 个鳍基因。**

- **鱼种树**（`genetics.ts: SPECIES`）：21 个节点组成二叉树。
  - 11 个叶子品种可以在补给店直接买卵；
  - 10 个杂交节点只能靠配对获得。
  - 两条鱼配对 → 子代鱼种 = 树上同时包含两者的**最小公共节点**
    （例：Goldshark + Flashfish → Coral Arowana）。
- **鳍基因环**（`genetics.ts: FIN_RING`）：21 个鳍基因排成一条环。
  - 子代 50% 继承父方、50% 继承母方；
  - 另有 12% 概率突变到**相邻**鳍基因；
  - 7 个稀有鳍基因被刻意夹在常见基因旁边，一次突变就能撞见，
    但要把「鱼种 + 鳍基因」凑成同一对仍然要规划好几代。
- **命名** = `鳍基因 + 鱼种`，例如 `Greenfin Spotanus`、`Canary Fire-Arrow`。
- **杂交弱质**：跨多个分支的子代会带 `fragile` 标记，健康慢性下降；
  「鱼缸环境」研究 2 级后解除。
- **图鉴**记录所有已发现的组合：4 列鱼卡 + 所选鱼种的 21 格鳍基因矩阵。

### 7 条魔法鱼

| 名字 | 鳍基因 / 鱼种 | 效果 |
| --- | --- | --- |
| Greenfin Spotanus | 绿鳍 + Spotanus | 同缸怀孕鱼每窝多产 1 条 |
| Spekled Leaffish | 斑点 + Leaffish | 同缸鱼饥饿速度 −30% |
| Crimson Comet | 绯红 + Comet | 同缸病鱼有概率自愈 |
| Canary Fire-Arrow | 金丝雀 + Fire-Arrow | 售价极高（建议标价 $475） |
| Oriental Goldbulb | 东方 + Goldbulb | 同缸鱼成长速度 +25% |
| Orange Snooper | 橘色 + Snooper | 同缸鱼持续回血 |
| Wasp Grouper | 胡蜂 + Grouper | 同缸子代突变率大增 |

魔法鱼必须**活着待在缸里**才生效；奖杯室每个相框都有一条对应谜语。

## 六、商业与销售

- **到店率**受广告研究、店招招牌、环境数值影响；店里的顾客数量会自然起伏。
- **购买意愿**由标价与「建议价」的比值决定：贴近建议价成交率最高，标太高没人买，标太低亏。
- **建议价** = 鱼种稀有度 + 鳍基因稀有度 + 成长期望的综合估价（面板里显示）。
- **成交反馈**：SOLD 卡片、店主人道谢、顾客头顶金币气泡。

## 八、顾客行为（鱼店）

顾客是一套**不会互相卡死**的轻量状态机，逻辑在 `sim.ts: storeVisualTick`：

| 阶段 | 行为 |
| --- | --- |
| `enter` | 从门口进店，按 BFS 路径走向随机落点（优先销售缸前，其次墙边、柜台附近） |
| `browse` | 驻足 1.5–4 秒看鱼，气泡显示 `?` `$` `♥` 等 |
| 换位置 | 45% 概率再逛一个落点，最多逛 2 次，超过必定离店 |
| `leave` | 先寻路到**门口** `DOOR = (0.935, 0.13)`，到门口后再跨出门槛，`x > 0.955` 时移除 |

保证不堵死的手段：

- **互不阻挡**：没有任何互相推挤/减速规则，只按各自路径前进（之前那套「相遇减速」正是门口死锁的根因，已移除）；
- **计时与到位解耦**：驻足计时一直在走，不会因为路点没走完就永远停在原地；
- **硬上限**：店内超过 9 人时，最早进店的顾客立刻离场；
- **8 秒卡死兜底**：一段时间没有实质位移就强制离店；
- **只走门**：进店 / 离店都从右侧门洞通过，不会贴着右墙穿出去。

移动与朝向：

- 速度 0.05–0.08（归一化坐标 / 秒），离店时稍快（×1.15），全部按 `dt` 推进（单帧 `dt` 上限 0.1 秒，防止卡帧瞬移）；
- 朝向按水平位移锁定，阈值 0.006（归一化坐标，约半个身位）防抖；
- 朝左 / 朝右使用**两套独立素材，不做水平镜像**（镜像会翻转迈步腿，看起来像倒退走）；
- 顾客按 `y` 排序绘制，前面的人挡住后面的人。

## 九、五个界面

1. **水缸**：程序化绘制的水族箱——渐变水体、光柱、砾石床、摇摆水草、假山 / 沉木、玻璃反光、气泡、食物颗粒。点鱼选中，底部 HUD 显示名字、状态、年龄、估值、健康与饱食。
2. **鱼店**：等距店内景（展示柜、海报、柜台、门头 SALE）。待售缸是**生成立绘**（玻璃缸 + 矮木架，白底泛洪抠图后运行时合成），缸内鱼按玻璃区域裁切绘制，价格牌钉在木柜正面。**店主**站在柜台内侧，下半身由背景像素重新覆盖，真正被柜台挡住。顾客是 25 张生成立绘，见上节。底部显示 SOLD 成交卡与标价控件。
3. **补给商店**：铁丝网商品墙 + 24 件商品 + 右侧说明卡与三层木架研究台。
4. **物种图鉴**：鱼种卡 + 所选鱼种的 21 格鳍基因 + 定价数字键盘。
5. **奖杯室**：金框相框 2/3/2 排列、谜语面板、统计报表。

## 十、视觉与美术管线

### 场景位图（8 张，`src/assets/art/`）

`store` / `supplies` / `species` / `trophy` / `tank-one` / `tank-two` / `tank-sale` + 销售缸立绘 `sale-tank`。
全部由图像模型生成、降采样到 1600px 宽、WebP q80，通过 `src/art.ts` 的 `getImage / coverRect / drawCover` 走 Vite 资源管线。
图片未加载时自动回退到早期的程序化场景，不会出现空白画面。

### 鱼店房间的运行时处理（`storeScene.ts`）

为了让底图在任何宽高比下都像一间完整的屋子，`getRoomCanvas()` 会做一次**按尺寸缓存的预处理**：

1. **地板打底**：先从底图采样一块干净地板做成平铺图案，铺满整帧；
2. **暗角转透明**：把画面下部与左右边缘的深色底座按亮度做成 alpha 渐变，露出下面的地板——因此左下、右下不会再出现黑色空洞，地板一直铺到画面边缘；
3. **统一光线**：不使用放射状暗角（会造成明暗分界），只叠一层几乎察觉不到的垂直渐变（顶 10% / 中 1.5% / 底 5%）。

### 人物立绘（`src/assets/npc/`，25 张）

- 9 个正面（店主 + 8 类顾客）、8 个朝右侧面、8 个朝左侧面；
- 图像模型不支持透明输出，因此按**绿幕**生成，再由 `scripts/build-npc-assets.ps1` 做
  `colorkey + despill` → 按 alpha 包围盒裁切 → 统一缩放到 520px 高（合计约 600KB）；
- 朝左 / 朝右是**两套独立素材**，运行时直接切换，**不做水平镜像**。

### 销售缸立绘

`saleTank.ts` 在运行时对 `sale-tank.webp` 做**白底泛洪抠图**，得到透明玻璃缸 + 木架，
`TANK_GLASS` 定义玻璃区域，缸内鱼被裁剪在玻璃范围内绘制。

## 十三、存档与离线补算

- 存档键：`localStorage['fish-tycoon-cn-v1']`；
- 存档内容包含随机数种子，读档后随机序列可复现；
- 关闭页面后按真实离开时长补算，上限 **1.5 鱼年**（避免长期放置导致全缸爆缸或团灭）；
- 菜单里有「重新开始」，会清空存档并重置为初始状态。

## 十四、测试桥与验证

`main.ts` 在 `globalThis.__OHMYGAME_PLAYTEST__` 上暴露一个**仅用于自动化验证**的桥：

| 方法 | 作用 |
| --- | --- |
| `snapshot()` | 返回当前状态摘要（现金、时间、鱼、顾客、研究、统计等） |
| `reset()` | 重置为初始状态 |
| `setSeed(seed)` | 固定随机种子，保证结果可复现 |
| `step(ms)` | 按毫秒推进模拟 |

正常玩法**不依赖**这个桥，缺少它游戏照常运行。

注意：`step()` 每次按不超过 **0.1 秒**的步长推进（模拟与顾客位置都会变），
但迈步动画与整体节奏仍由 `requestAnimationFrame` 驱动，因此在自动化里验证“走位是否自然”时，
应当用真实时间等待，而不是连续调用 `step()`。

## 十五、已知限制

- 每个顾客目前只有**一个行走姿势**（没有交替腿帧），走动时更像"平移"，而不是完整步态；
  如需更自然的步频，可再生成 8 张第二帧立绘交替播放。
- 店主只有正面立绘，不会走到店内与顾客互动。
- 场景位图是固定机位，窗口比例极端（尤其超宽屏）时画面上下会被裁切。
- 顾客路径规划是 36×22 网格的 BFS，只有拐点级的绕行，没有贴墙平滑；近距离绕行时步子会略显方正。
- 音效为程序化合成，没有背景音乐。

## 十六、变更记录
